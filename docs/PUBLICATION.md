# Publication: one piece of work, multiple credible representations

**Work product:** software, preserved source data, normalized records, SQLite, tests, research, role evidence and actual application outcomes.

**Proof/portfolio:** Git history, README, architecture, demonstrable local UI, Build Log, technical write-up, Case File, Field Note, failure/correction account and optional Proof Capsule (30–90 second demonstration).

**Separation of views:** operational files may contain contact details or private application notes; curated public displays emphasize evidence, code, source-grounded research and accurate statuses. The owner controls which non-secret personal information is shared. Credential and access-token strings should not be published accidentally.

Every important application should generate reusable research and proof **without creating another full-time content production workload**. Publish a video or social post only if it materially helps document a real working artifact; blank templates are not public releases.

Potential public outputs later: company Case Files, field observations, technical reports, company/role research, industry hiring summaries, source-backed graphs and a longitudinal dashboard. Until they exist, mark them as *planned* or *template* rather than accomplished.
