# Vision, identity and governing principles

**Canonical public project:** Building My Way Into AI  
**Tagline:** Breaking into the AI industry one real application at a time.

**ProofLoop** is the operational/application system. **AI Observatory** is the company/industry investigation and intelligence layer. The **Proof Graph**, ledgers, logs, Case Files, Field Notes, evidence states, Git documentation and Proof Capsules are shared infrastructure—not rival projects.

**Thesis:** Can a real applicant enter AI by investigating companies and roles, applying to them, learning what the market actually requires, building useful tools in response, documenting claims and mistakes, and preserving evidence of genuine capability growth? The company research, software, skill evidence, applications, and public narrative must feed one loop.

The public identity is curious, technical, investigative, evidence-driven, creative, willing to expose imperfections, and occasionally entertaining—never dependent on exaggerating current qualifications or pretending the project was built unassisted.

## The principles that govern this project

1. **Apply and build from the first real case**; no giant prerequisite curriculum.
2. Use documented prior experience honestly; don't manufacture skills, employment, old commits or application outcomes.
3. Application needs drive investigation, just-in-time learning and bounded Proof Sprints.
4. Separate missing ability from missing evidence of an existing ability.
5. Every important application should leave code, research, evidence, insight, or re-usable workflow.
6. Connect claims to original sources and assign evidence states; preserve uncertainty and contradictions.
7. Build work product **and** inspectable proof (tests, documentation, Git and demo).
8. Expose mistakes, changes of mind, genuine failures and correction history.
9. Keep stack free or low-cost where reasonably possible.
10. Turn actual project work into public evidence; don't create a second full-time content job.
11. Measure outcomes and time, including rejected applications; record unknown rather than invented baselines.
12. Let the industry inform learning priorities as more roles accumulate.
13. Every application eventually closes as submitted or abandoned with an actual reason.
14. Reuse the same coherent technical system across related applications rather than building five unrelated projects.
15. **Employment remains the mission.** No infrastructure improvement should indefinitely delay the submission process.

## The public formula

**Apply → investigate → learn → build → prove → track → map → document → publish → measure → improve → apply again.**

This is a multi-attempt longitudinal experiment. The original physical `Day1` folder is Attempt #001 (OpenAI) despite spanning multiple days. Its historic 817-role HTML prototype and current 816-role API pipeline both belong in the history, but as distinct datasets.
